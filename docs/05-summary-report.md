## 1. 项目背景与小组分工
### 项目背景
本实验以“校园活动报名与签到管理系统”为统一项目背景。该系统旨在支持活动发布、学生报名、名单审核、二维码签到、签到统计和活动总结导出等基本功能。本次实验聚焦软件项目管理过程，通过 Git 版本管理工具完成项目初始化、三级 WBS 分解、进度计划编制、配置管理、分支协作、冲突解决及总结报告提交，重点训练项目管理成果的形成、版本受控和协作留痕能力，不要求实现完整的业务系统。

### 项目目标
- 建立统一的项目仓库与目录结构
- 完成围绕交付物的三级 WBS 分解
- 制定简化进度计划（含活动、工期、前置关系、责任人）
- 制定配置管理方案（配置项识别、分支策略、提交与合并规则）
- 制造并解决一次 Git 冲突，记录解决过程
- 全体成员共同完成总结报告，并提交至 main 分支

## 2. WBS 分解思路
本次项目采用自上而下逐层细化的分解思路，以整体项目作为顶层任务，结合实验实训内容与项目交付要求，依次划分一级、二级、三级工作任务。整体按照项目准备、文档编制、版本管控、实操练习、项目收尾五大模块拆分，再依据组员岗位职责拆分细分任务，确保每项工作内容清晰明确、权责对应。所有分解任务贴合实验要求，以文档编写、流程规范、团队协作为核心，任务划分无重复、无空缺，能够直接对接进度计划进行工期排布，方便小组有序开展各项工作。

## 3. 进度安排依据
本次进度计划以课程实验要求、任务难易程度、实训时长以及人员分工为主要制定依据。先梳理全部必须完成的实验任务，理清各项工作的先后逻辑与前置关系，按照先后顺序排布工作流程。再结合每位成员负责的工作内容合理分配工期，明确每项任务完成时限与验收标准。由计划负责人统一统筹排布，项目经理全程监督进度，出现任务延迟及时微调安排，保障小组能够在规定时间内顺利完成全部实验内容。

## 4. 配置管理与协作过程
实验全程使用Git完成版本控制与团队协同工作，由配置管理员统一搭建公开远程仓库，统一规范项目目录结构。团队采用main、dev、feature-*三级分支模式开展协作，严格遵守既定文档命名、分支命名、提交备注规范，将所有项目文档、资料全部纳入配置管理范围。组员在个人功能分支完成编写工作后，先提交本地仓库再推送远程分支，经审核后合并至开发分支，全部内容完成后统一合并至主分支保存最终版本，做到修改可追溯、版本有留存、协作流程标准化。

## 5. 冲突解决过程记录
小组模拟真实团队协作场景开展冲突实验，多名成员同时拉取同一版本文件，在文档同一位置进行不同内容修改并提交推送，合并分支时产生Git内容冲突。出现冲突后，全体成员先同步拉取远程最新代码，统一本地项目版本；共同核对冲突区域内容，结合实验需求筛选保留有效内容，手动删除冲突标识语句，整理完善文档内容；修改无误后重新完成暂存、提交、推送操作，顺利完成分支合并，完整掌握冲突排查、修改、合并全套处理流程。

## 6. 经验与问题
### 实训收获
通过本次综合实验，小组全体成员熟练掌握Git仓库搭建、分支使用、提交推送、版本同步以及冲突解决等实操技能，将课堂上学到的项目管理理论知识运用到实际实训当中。同时明确项目团队不同岗位的工作职责与配合方式，熟练掌握WBS分解、进度规划、配置管理等实用项目管理方法，养成规范编写文档、规范进行版本提交的良好习惯，大幅提升团队协作能力与项目实操能力。

### 遇到的问题
1. 校园网络存在访问限制，部分成员无法正常连接GitHub，出现克隆失败、推送超时等问题，只能更换网络完成操作，影响协作效率。
2. 初期使用IDEA终端时出现路径异常、无法快速定位项目目录的问题，对Git命令使用造成不便。
3. 初次进行分支合并操作时操作不够熟练，容易出现提交错误、分支混用等失误。
4. 前期制定任务分工与进度计划时，部分任务划分不够细致，工期安排不够合理，后期经过讨论调整才完善到位。

### 整体总结
本次软件项目管理综合实验顺利完成所有既定任务，完整产出各项实验文档，圆满达成实验学习目标。在今后的学习中，我们会继续巩固项目管理相关知识与Git工具使用技巧，优化任务规划与分工方式，规避本次实训出现的各类问题，不断提升自身项目管理水平与团队协作能力。
